# 入社2週間目に、本番のブランチを消しかけた話

エンジニアになって最初にやらかした話を書きます。もう3年前のことですが、いまでもたまに夢に見ます。

## あの日のこと

入社して2週間目。研修が終わって、小さな修正のタスクをもらったばかりでした。ボタンの文言を直すだけの、本当に小さな修正です。

作業を終えて、プルリクエストを出す前に、手元のブランチを整理しようと思いました。研修中に作った練習用のブランチがたくさん残っていて、見た目が気持ち悪かったんです。

そこで、ネットで見つけたコマンドをそのまま打ちました。

```
git branch | grep -v "main" | xargs git branch -D
```

「main 以外のブランチをまとめて消す」というものです。ここまでは、手元の話なのでまだよかった。

問題はその次です。リモートにも練習用のブランチが残っていたので、同じ感覚で消そうとして、リモートのブランチを一覧から消すコマンドを書きはじめました。そのとき、対象を絞る grep の条件を間違えていて、一覧に `release/2.4` が入っていたんです。翌週に出す予定の、リリース用のブランチでした。

## 止めてくれたのは

Enter を押す直前に、隣の席の先輩が画面をのぞきこんで「それ、何消そうとしてる？」と聞いてきました。

画面を見せながら説明しているうちに、自分でも一覧に `release/2.4` があることに気づきました。手が冷たくなったのを覚えています。

あとで聞いたら、先輩は僕のターミナルに `xargs` と `push origin --delete` が並んでいるのが見えて、反射的に声をかけたそうです。

## そのあと変えたこと

この件で、チームではいくつかルールができました。

- `main` と `release/*` のブランチは、GitHub の保護設定で削除できないようにする
- 複数のブランチを消すときは、まず一覧を出して目で確認してから消す
- ネットで拾ったコマンドは、意味がわからないまま本番に関わるリポジトリで打たない

一つ目は、もっと早くやっておくべきだった、とチームリーダーが言っていました。人が気をつけるより、仕組みで止めたほうが確実です。

## いま思うこと

いまは僕が新人の画面をのぞきこむ側になりました。`--force` や `-D` が見えると、つい「それ何してる？」と聞いてしまいます。うるさい先輩だと思われているかもしれませんが、あの日の自分を思い出すと、聞かずにはいられません。

やらかしは、ないに越したことはありません。でも、やらかしかけたことを話せる職場だったのは、運がよかったなと思っています。
