# nas-backup

事務所のNASにある共有フォルダを、毎晩外付けHDDとクラウドストレージにバックアップするためのスクリプトです。社内の情シス担当（兼任）が、引き継ぎのために書いています。

中身は `rsync` と `rclone` を呼んでいるだけの小さなシェルスクリプトです。凝ったことはしていないので、何かあっても中を読めば大体わかると思います。

## 何をしているか

毎晩 2:00 に、次の順で動きます。

1. NASの `/volume1/share` を、外付けHDD（`/volumeUSB1/usbshare/backup`）に `rsync` でコピー
2. 同じフォルダを、クラウドストレージに `rclone` で同期
3. 結果をログに書き、失敗したときだけメールで知らせる

外付けHDDのほうは、日付ごとのフォルダに差分を残しているので、過去30日分ならどの日の状態にも戻せます。クラウドのほうは最新の状態だけです。

## 動かしている場所

- NAS：事務所のサーバーラックにあるもの（管理画面は `http://192.168.1.10:5000`）
- スクリプトの置き場所：`/volume1/scripts/nas-backup/`
- 実行のスケジュール：NASの「タスクスケジューラ」に登録しています

## 初めて設定するとき

NASを入れ替えたときなど、一から設定し直す場合の手順です。

1. このリポジトリの中身を、NASの `/volume1/scripts/nas-backup/` に置きます。
2. `config.example.sh` を `config.sh` という名前でコピーし、中のパスとメールアドレスを書き換えます。
3. `rclone config` を実行して、クラウドストレージの接続設定を作ります。リモート名は `cloud` にしてください（スクリプトがこの名前を前提にしています）。
4. 手動で一度動かして、エラーが出ないか確かめます。

   ```bash
   sudo /volume1/scripts/nas-backup/backup.sh
   ```

   初回は全部コピーするので、数時間かかります。
5. NASの管理画面で「タスクスケジューラ」を開き、毎日 2:00 に上のコマンドを root で実行するタスクを作ります。

## ファイルを戻したいとき

「昨日消したファイルを戻してほしい」と言われたら、外付けHDDから戻すのがいちばん早いです。

```bash
ls /volumeUSB1/usbshare/backup/
# 2026-11-23  2026-11-22  2026-11-21 ... と日付のフォルダが並んでいます
```

戻したい日のフォルダから、該当のファイルを元の場所にコピーしてください。上書きしてしまわないよう、いったん別の名前でコピーしてから本人に確認してもらうのが安全です。

外付けHDDが壊れている場合は、クラウドから戻します（`rclone copy cloud:share/<パス> <戻し先>`）。ただし、クラウドには最新の状態しかないので、昨日消したファイルはクラウドからも消えています。その場合は、クラウドストレージ側のゴミ箱（30日間保存）を見てください。

## ログとエラー

- ログ：`/volume1/scripts/nas-backup/logs/` に日付ごとに出ます。古いものは90日で消えます。
- 失敗したときは、`config.sh` に書いたアドレスにメールが届きます。

よくある失敗は次の2つです。

- **外付けHDDが見つからない**：誰かが抜いたか、NASが再起動したあとにマウントされていない。差し直すとたいてい直ります。
- **rcloneの認証が切れた**：クラウドのパスワードを変えたときなどに起きます。`rclone config reconnect cloud:` で入り直してください。

## 気をつけてほしいこと

- 外付けHDDは、半年に一度くらいは実際にファイルを戻してみて、ちゃんと読めるか確認してください。バックアップは、戻せることを確かめて初めて意味があります。
- 外付けHDDは5年目に入っています。そろそろ交換を考えてください。

わからないことがあれば、前任の情シス担当（総務部）に聞いてください。
