| 項目 | 内容 |
|------|------|
| 文書バージョン | 1.0.0 |

---

## 1. 概要

本仕様書は、認証基盤 VC-Data API（`/v1/auth-platform/vc-data`）が返却するVerifiable Credential（VC）の属性スキーマを標準化・文書化することを目的とする。

VC属性の定義を明確にすることで、以下を実現する。

- フロントエンド・バックエンド間のインターフェース整合性の確保
- 認証基盤へ提供するデータ構造の標準化
- VC発行時の属性バリデーション基準の明示
- 将来的なスキーマ変更に対する追跡可能性の担保

VCの種別（`vctype`）には現在 `climb`（入山準備完了証）と `donation`（募金完了証）の2種類が存在する。

---

## 2. 入山準備完了証（vctype: climb）

入山計画と準備状況を証明するVCである。ユーザーがマナーチェックおよび誓約書の提出を完了したことを示す。

### 2.1 属性一覧

| 属性名 | 型 | 必須/任意 | 説明 | 値の例 | 制約 |
|--------|-----|-----------|------|--------|------|
| `version` | String | 必須 | スキーマバージョン | `"1.0.0"` | セマンティックバージョニング（x.y.z形式） |
| `status` | Integer | 必須 | レスポンスステータスコード | `200` | 固定値: `200` |
| `verification_count` | Integer | 必須 | 確認回数 | `1` | 正常時は`1`、空値時は`0` |
| `departure_date` | String | 必須 | 入山日（YYYY-MM-DD形式） | `"2026-08-01"` | String型。空値時は`"1900-01-01"` |
| `descent_date` | String | 必須 | 下山日時（ISO 8601形式） | `"2026-08-03T00:00:00Z"` | ISO 8601形式。空値時は`"1900-01-01T00:00:00Z"` |
| `mountain_area` | String | 必須 | 山域名称 | `"○○山域"` | 空値時は空文字列`""` |
| `lodging` | String | 必須 | 宿泊山小屋名称 | `"○○山荘"` | 空値時は空文字列`""` |
| `companions` | String | 必須 | 同行者情報（カンマ区切り） | `"同行者A(男性), 同行者B(女性)"` | 書式: `"名前(性別)"`のカンマ区切り。同行者なしの場合は空文字列`""` |
| `emergency_contact` | String | 必須 | 緊急連絡先（復号化済み） | `"090-0000-0000"` | 暗号化フィールドより復号化。未設定時は`"未設定"`、空値時は空文字列`""` |
| `preexisting_conditions` | String | 必須 | 既往症（復号化済み） | `"高血圧"` | 暗号化フィールドより復号化。未設定時は`"未設定"`、空値時は空文字列`""` |
| `prepare_for_climbing` | String | 必須 | 登山準備状況 | `"マナーチェック・誓約書の提出済"` | 固定値: `"マナーチェック・誓約書の提出済"` |

### 2.2 JSONレスポンス例（正常ケース）

ユーザーが存在し、入山計画が取得できた場合のレスポンス。

```json
{
  "version": "1.0.0",
  "status": 200,
  "verification_count": 1,
  "departure_date": "2026-08-01",
  "descent_date": "2026-08-03T00:00:00Z",
  "mountain_area": "○○山域",
  "lodging": "○○山荘",
  "companions": "同行者A(男性), 同行者B(女性)",
  "emergency_contact": "090-0000-0000",
  "preexisting_conditions": "なし",
  "prepare_for_climbing": "マナーチェック・誓約書の提出済"
}
```

### 2.3 空値パターン

ユーザーが存在しない場合、または指定した`source_id`に対応する入山計画が見つからない場合のレスポンス。キー構造は正常ケースと同一だが、各属性に空・デフォルト値が設定される。

```json
{
  "version": "1.0.0",
  "status": 200,
  "verification_count": 0,
  "departure_date": "1900-01-01",
  "descent_date": "1900-01-01T00:00:00Z",
  "mountain_area": "",
  "lodging": "",
  "companions": "",
  "emergency_contact": "",
  "preexisting_conditions": "",
  "prepare_for_climbing": "マナーチェック・誓約書の提出済"
}
```

## 3. 募金完了証（vctype: donation）

山域・自治体への寄付完了を証明するVCである。直接支援またはふるさと納税による寄付実績を示す。

### 3.1 属性一覧

| 属性名 | 型 | 必須/任意 | 説明 | 値の例 | 制約 |
|--------|-----|-----------|------|--------|------|
| `version` | String | 必須 | スキーマバージョン | `"1.0.0"` | セマンティックバージョニング（x.y.z形式） |
| `status` | Integer | 必須 | レスポンスステータスコード | `200` | 固定値: `200` |
| `donation_type` | String | 必須 | 寄付種別（日本語） | `"直接支援"` | `"直接支援"` または `"ふるさと納税"`。DBの英語値（`direct_support` / `furusato_nozei`）を変換して返却。空値時は空文字列`""` |
| `donation_recipient` | String | 必須 | 寄付先名称 | `"○○保全基金"` | 山域名または自治体名。未設定時は`"未設定"`、空値時は空文字列`""` |
| `donation_amount` | Integer | 必須 | 寄付金額（円） | `5000` | 整数値。空値時は`0` |
| `donation_date` | String | 必須 | 寄付日（YYYY-MM-DD形式） | `"2026-07-15"` | `donations.created_at`をYYYY-MM-DD形式にフォーマット。空値時は空文字列`""` |

### 3.2 JSONレスポンス例（正常ケース）

ユーザーが存在し、寄付レコードが取得できた場合のレスポンス。

```json
{
  "version": "1.0.0",
  "status": 200,
  "donation_type": "直接支援",
  "donation_recipient": "○○保全基金",
  "donation_amount": 5000,
  "donation_date": "2026-07-15"
}
```

### 3.3 空値パターン

ユーザーが存在しない場合、または指定した`source_id`に対応する寄付レコードが見つからない場合のレスポンス。キー構造は正常ケースと同一だが、各属性に空・デフォルト値が設定される。

```json
{
  "version": "1.0.0",
  "status": 200,
  "donation_type": "",
  "donation_recipient": "",
  "donation_amount": 0,
  "donation_date": ""
}
```

## 4. バージョニング

`version`フィールドは**セマンティックバージョニング（Semantic Versioning）**に従う。

### バージョン形式

```
<MAJOR>.<MINOR>.<PATCH>
```

| 区分 | インクリメント条件 |
|------|-------------------|
| `MAJOR` | 後方互換性のない破壊的変更（属性の削除・型変更など） |
| `MINOR` | 後方互換性を保った機能追加（新属性の追加など） |
| `PATCH` | 後方互換性を保ったバグ修正・説明の変更 |

### バージョン管理ルール

- 全VCタイプ（`climb` / `donation`）は現在 `"1.0.0"` で統一。
- スキーマ変更時は本仕様書の「5. 変更履歴」に記録する。
- MAJORバージョンの変更時は、認証基盤との事前調整が必須。
- `version`の値はAPIレスポンスのハードコード値として管理される（`auth_platform.py`内）。
